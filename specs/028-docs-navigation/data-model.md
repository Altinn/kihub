# Data Model: Documentation Navigation for Pages

Research: R6, R7, R15. Contracts: [page-hierarchy.md](./contracts/page-hierarchy.md),
[headings-toc.md](./contracts/headings-toc.md).

## 1. Page (`pages`, changed)

Existing fields are unchanged: `title`, `slug` (unique, one segment, reserved list), `summary`,
`body`, `author`, `_status`, versions.

New fields:

- **`parent`**: relationship → `pages`, optional, one. Label «Overordnet side», sidebar.
  Description: «Valgfritt. Siden havner under denne i adressen og i menyen. Høyst tre nivåer.»
  Column `pages.parent_id` (FK `ON DELETE SET NULL`, indexed); version column
  `_pages_v.version_parent_id`.
- **`order`**: number, default 100. Label «Rekkefølge», sidebar. Description: «Lav verdi først blant
  sidene med samme overordnede side; like verdier sorteres alfabetisk.» Columns `pages.order`,
  `_pages_v.version_order`.
- **`address`** (optional, FR-018): `ui` field, no column. Shows the computed address.

Changed field description on `slug`: «Sidens adresseledd. Adressen blir /<overordnet>/<adresse>, eller
/<adresse> uten overordnet side. Må være unik blant alle sider og kan ikke være en adresse KI Hub
allerede bruker.»

### Invariants

- **H1** `parent !== id`.
- **H2** Following `parent` from any page never returns to that page (no cycles).
- **H3** Depth ≤ 3: a page without parent is level 1; level(child) = level(parent) + 1.
- **H4** `slug` unique across all pages (unchanged), so the last address segment identifies a page.
- **H5** Every `slug`, at any level, passes `validatePageSlug` (pattern and reserved list), unchanged.

H1–H3 are enforced by the `beforeValidate` hook on every save (R9). H4–H5 are enforced as today.

### State transitions

- **Set or change parent** → the page's address changes on publish; old addresses redirect (R7).
- **Clear parent** → the page becomes top-level at `/<slug>`.
- **Delete parent** → database sets `parent_id` to null on children; they become top-level.
- **Change slug** → the page's and its descendants' addresses change; old addresses ending in the old
  slug become 404 (as today).
- **Unpublish root** → its published descendants stay reachable; readers see no section menu.

## 2. Derived (not stored)

- **Address** of page P: `'/' + [slug of each ancestor from the top] + slug(P)` joined with `/`.
  Computed by `pageAddress(chain)` in `lib/page-tree.ts`.
- **Section** of page P: its top-level ancestor R (or P itself) and all published descendants of R,
  ordered by `order`, then `title` (Norwegian collation, as `byOrderThenTitle`).
- **Heading** in a body: `{ level: 2 | 3 | 4, text, id }`, from `extractHeadings(body)`.
- **Table of contents**: the headings nested by level.

## 3. Migration `<ts>_pages_hierarchy` (additive)

```sql
ALTER TABLE "pages" ADD COLUMN "parent_id" integer;
ALTER TABLE "pages" ADD COLUMN "order" numeric DEFAULT 100;
ALTER TABLE "_pages_v" ADD COLUMN "version_parent_id" integer;
ALTER TABLE "_pages_v" ADD COLUMN "version_order" numeric DEFAULT 100;
ALTER TABLE "pages" ADD CONSTRAINT "pages_parent_id_pages_id_fk"
  FOREIGN KEY ("parent_id") REFERENCES "public"."pages"("id") ON DELETE set null ON UPDATE no action;
ALTER TABLE "_pages_v" ADD CONSTRAINT "_pages_v_version_parent_id_pages_id_fk"
  FOREIGN KEY ("version_parent_id") REFERENCES "public"."pages"("id") ON DELETE set null ON UPDATE no action;
CREATE INDEX "pages_parent_idx" ON "pages" USING btree ("parent_id");
CREATE INDEX "_pages_v_version_version_parent_idx" ON "_pages_v" USING btree ("version_parent_id");
```

Indicative: the real file is generated by `payload migrate:create` (in `MEDIA_STORAGE_MODE=azure`) and
reviewed. `down` drops the constraints, indexes and columns. No data backfill: existing rows get
`parent_id = NULL` and `order = 100`, which keeps every address and behaviour (FR-019).
